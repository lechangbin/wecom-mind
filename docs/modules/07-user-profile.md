# 07. 用户画像模块

## 1. 模块职责

用户画像模块负责根据用户消息和会话摘要生成结构化画像。

负责：

- 选择待分析用户。
- 汇总用户近期消息。
- 汇总用户参与会话摘要。
- 调用 `user_profile_analysis` Dify 工作流。
- 校验画像事实。
- 写入画像事实。
- 更新用户画像快照。
- 保留画像版本。

不负责：

- 原始消息入库。
- Dify Prompt 编写。
- 前端画像展示样式。

## 2. 画像内容

建议画像字段：

- 关注方向。
- 业务角色。
- 常见问题。
- 行为偏好。
- 个人信息线索。
- 风险或敏感提示。

每条画像事实必须有：

- `fact_type`
- `label`
- `description`
- `evidence_msgids` 或 `evidence_conversation_nos`
- `confidence`

## 3. 分析触发

触发方式：

- 定时任务。
- 用户新增消息达到阈值。
- 用户参与新会话达到阈值。
- 手动触发。

MVP 建议：

- 先支持手动触发和每日定时触发。

## 4. 处理流程

1. 选择 userid。
2. 查询用户近期消息。
3. 查询用户参与会话摘要。
4. 读取当前画像快照。
5. 调用 Dify Gateway。
6. 校验输出 userid 一致。
7. 校验证据消息存在。
8. 写入 `user_profile_facts`。
9. 生成新版本 `user_profiles` 快照。

## 5. 低置信度策略

建议规则：

- `confidence >= 0.75`：可进入画像快照。
- `0.5 <= confidence < 0.75`：保存事实但标记低置信度。
- `confidence < 0.5`：不进入画像事实，或仅保留在 ai_runs。

## 6. MVP 实现范围

必须实现：

- 单用户画像分析。
- Dify 输出校验。
- 画像事实写入。
- 画像快照查询。

可延后：

- 画像冲突合并。
- 画像过期机制。
- 人工审核画像。

## 7. 验收标准

- 能对一个用户生成画像摘要。
- 每条画像事实有证据和置信度。
- Dify 返回其他 userid 时不会写库。
- 画像更新能生成新版本。
