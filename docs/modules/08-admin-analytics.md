# 08. 管理与统计模块

## 1. 模块职责

管理与统计模块为后续前端和课程展示提供查询接口。

负责：

- 总览统计。
- 消息查询。
- 群聊列表。
- 用户列表。
- 会话摘要查询。
- 用户画像查询。
- Dify 调用日志查询。
- 发送记录查询。

不负责：

- 复杂前端页面设计。
- 实时大屏。
- 复杂权限系统。

## 2. MVP 页面对应接口

### 2.1 数据总览

接口：

- `GET /api/dashboard/overview`

指标：

- 今日消息数。
- 累计消息数。
- 活跃群聊数。
- 活跃用户数。
- 今日机器人触发次数。
- Dify 调用次数。
- Dify 成功率。
- 平均响应耗时。
- 待处理任务数。
- 失败任务数。

### 2.2 群聊消息

接口：

- `GET /api/chats`
- `GET /api/chats/{chatid}/messages`
- `GET /api/stats/messages`

指标：

- 群消息趋势。
- 群活跃排行。
- 消息类型分布。
- 用户发言排行。

### 2.3 会话摘要

接口：

- `GET /api/conversations`
- `GET /api/conversations/{conversation_no}`

展示：

- 会话编号。
- 标题。
- 摘要。
- 关键词。
- 参与人。
- 起止时间。

### 2.4 用户画像

接口：

- `GET /api/users`
- `GET /api/users/{userid}/profile`

展示：

- 用户基础信息。
- 画像摘要。
- 画像事实。
- 证据消息。
- 置信度。

### 2.5 AI 运行日志

接口：

- `GET /api/ai-runs`
- `GET /api/ai-runs/{run_id}`

展示：

- 工作流编码。
- 版本。
- 输入摘要。
- 输出摘要。
- 状态。
- 耗时。
- 错误信息。

## 3. 查询原则

- MVP 阶段直接从业务表聚合。
- 数据量变大后再增加统计宽表。
- 查询接口必须分页。
- 运行日志默认不展示完整敏感输入。

## 4. MVP 实现范围

必须实现：

- 总览接口。
- 消息列表接口。
- 会话摘要列表接口。
- 用户画像详情接口。
- Dify 调用日志列表接口。

可延后：

- 权限角色。
- 导出 Excel。
- 高级筛选。
- 实时刷新。

## 5. 验收标准

- 前端可以通过接口展示基础看板。
- 能按群查看消息。
- 能查看会话摘要。
- 能查看用户画像。
- 能追踪一次 Dify 调用的输入输出和状态。
